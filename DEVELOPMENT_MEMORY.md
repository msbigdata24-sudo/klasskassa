# Апельсин — память разработки

Обновлено: 2026-05-01

## Что это за файл

Короткая «оперативная память» проекта: что уже внедрено, что важно не потерять, и с какого места продолжать дальше.

## Текущее состояние

- Проект активно развивается как веб-приложение для совместного учета расходов (поездки, жилье, друзья, мини-команды).
- Последний деплой выполнен после коммита с заменой текста на главной: `Казань май` -> `Сочи май`.
- В репозитории Апельсина больше не должно быть блока `Sales MVP` на главной.
- Материалы/файлы VoxMentor вынесены из Апельсина в отдельную папку `Стратеикс`.

## Что уже реализовано (ключевое)

### 1) Метрики и аналитика
- Расширение до формата «Метрики v3»: обзор по группам и активности тестеров.
- Добавлены расширенные типы событий (изменения расходов/погашений, конфликты версий, recurring-события и др.).
- Отдельный блок «здоровье офлайн-синка» был добавлен и затем удален по запросу.

### 2) Уведомления и непрочитанные
- Улучшен UX по непрочитанным сообщениям и подсказкам.
- Добавлена отдельная страница центра уведомлений.
- Добавлены/доработаны push-уведомления и настройки уведомлений.
- Доработан механизм обновления статуса непрочитанных через отдельный API.

### 3) Подтверждение долгов и споры
- Реализовано подтверждение/оспаривание долга участником.
- Реализован админский разбор споров.
- Добавлен таймлайн событий по подтверждениям/спорам.
- В ряде ответов API передается список уведомленных пользователей для понятных toast-сообщений.

### 4) Офлайн-режим и синк
- Внедрены офлайн-очереди (IndexedDB) для операций, включая мутации.
- Реализован фоновый запуск синка и обработка ошибок/конфликтов.
- Добавлена проверка версий (`baseVersionAt`) и серверный `409 Conflict` для защиты от перезаписи свежих данных.
- Добавлен offline banner / индикатор состояния.
- Для устойчивой офлайн-навигации внедрен `OfflineSafeLink` (в том числе для перехода из списка групп в группу).
- Service Worker расширен кэшированием shell/навигации и fallback-страницей офлайна.

### 5) Группы, архив, UX
- Реализована логика архивации групп (при выполнении условий).
- В списке групп есть разделение на активные и архивные.
- Улучшены кнопки (пилот soft-3D на ключевых действиях).

### 6) Recurring расходы
- Добавлены действия редактирования/паузы/удаления шаблона.
- Добавлено явное пояснение к интервалу (например, `30 = раз в 30 дней`).
- Добавлена защита от дублей активных recurring-шаблонов.

### 7) Лэндинг и контент
- Доработаны блоки главной, FAQ (раскрытие по `+`), юридический минимум, Telegram-ссылки.
- Обновлен текст-пример названия группы: теперь `Сочи май`.

## Важные договоренности по процессу

- Пользователь не технарь: git-решения и безопасный выбор файлов на стороне агента.
- Перед коммитом не брать лишние изменения в грязном рабочем дереве.
- Коммитить и пушить только то, что явно согласовано.

## Что проверить после деплоя (быстрый чек-лист)

- Главная показывает `Сочи май`.
- Офлайн: переход `Группы -> Конкретная группа` не падает без интернета.
- Непрочитанные сообщения корректно исчезают после прочтения.
- Архив групп отображается и доступен.
- Подтверждение/оспаривание долгов работает по сценарию.

## Следующий фокус разработки

- Усиление офлайн-сценария «сутки офлайн»:
  - надежная работа длинных офлайн-очередей,
  - офлайн-создание новых сущностей (в т.ч. групп),
  - стабильная синхронизация больших пачек при возврате сети,
  - кэш ключевых маршрутов для предсказуемой навигации.
