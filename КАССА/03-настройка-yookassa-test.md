# YooKassa: настройка тестового режима

Этот файл для этапа беты, когда реальные деньги не принимаются.

## 1) Личный кабинет

- [ ] Создать/войти в аккаунт YooKassa.
- [ ] Активировать тестовый режим (sandbox).
- [ ] Получить тестовые `shopId` и `secretKey`.
- [ ] Создать webhook URL для dev/stage.

## 2) Переменные окружения (пример)

Добавьте в `.env` (имена можно адаптировать под ваш код):

```bash
PAYMENTS_PROVIDER=yookassa
YOO_KASSA_SHOP_ID=...
YOO_KASSA_SECRET_KEY=...
PAYMENTS_WEBHOOK_SECRET=...
APP_BASE_URL=https://your-dev-domain.example
```

## 3) Что должно быть в коде

- `POST /api/pro/gift/create`
  - создает GiftPurchase в статусе `CREATED`,
  - создает платеж у провайдера,
  - сохраняет `providerPaymentId`,
  - возвращает `confirmationUrl` для редиректа.
- `POST /api/payments/webhook`
  - проверяет подпись/секрет,
  - маппит статусы провайдера в `PAID/CANCELED/REFUNDED`,
  - обновляет GiftPurchase идемпотентно.
- `POST /api/pro/gift/claim`
  - разрешает активацию только для `PAID`,
  - проверяет срок токена,
  - в транзакции продлевает `proUntil` и создает GiftClaim.

## 4) Проверка в тестовом режиме

- [ ] Тест "успешная оплата" -> webhook `PAID` -> claim -> Pro активирован.
- [ ] Тест "отмена" -> webhook `CANCELED` -> claim запрещен.
- [ ] Тест "возврат" -> webhook `REFUNDED` -> доступ корректно ограничивается по правилам.
- [ ] Тест "дубликат webhook" -> повтор не ломает состояние.

## 5) Готовность к переходу в прод

Переключение в прод только после:

- [ ] успешного прохождения всех тест-кейсов;
- [ ] проверки логирования и алертов;
- [ ] подписанного договора с провайдером;
- [ ] финальной проверки оферты/возвратов/ПДн.
