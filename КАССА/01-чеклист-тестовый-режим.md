# Чеклист: тестовый режим (без приема реальных платежей)

## 1) Режим работы

- [ ] Зафиксировано правило: реальные оплаты выключены до отдельного решения.
- [ ] Во внешних каналах и внутри продукта нет обещания "уже можно оплатить".
- [ ] Все тестовые пользователи предупреждены, что это бета.

## 2) Техподготовка проекта

- [ ] Применена Prisma-схема:
  - `npx prisma db push` (или `npx prisma migrate dev -n add_gift_purchase_flow`)
  - `npx prisma generate`
- [ ] В `.env` добавлен `PAYMENTS_WEBHOOK_SECRET` (случайная строка).
- [ ] Эндпоинты доступны локально/на dev:
  - `POST /api/pro/gift/create`
  - `POST /api/payments/webhook`
  - `POST /api/pro/gift/claim`

## 3) Тестовые данные и безопасность

- [ ] Используются только тестовые ключи/тестовые платежи провайдера.
- [ ] Нет хранения данных банковских карт в проекте.
- [ ] В логах не сохраняются секреты и чувствительные данные.
- [ ] Включен базовый rate-limit на create/claim/webhook (если еще не включен - добавить перед продом).

## 4) Минимум в интерфейсе для беты

- [ ] На экранах оплаты есть пометка "Тестовый режим".
- [ ] Добавлено сообщение после "успешной оплаты", что операция учебная/тестовая.
- [ ] На экране активации gift-token показаны понятные ошибки:
  - токен не найден,
  - токен истек,
  - токен уже активирован,
  - платеж еще не подтвержден.

## 5) Обратная связь от бета-тестеров

- [ ] Есть единый канал фидбека (форма/чат/таблица).
- [ ] Для каждого кейса фиксируется:
  - сценарий,
  - ожидание,
  - фактический результат,
  - скриншот/видео,
  - окружение (web/mobile, браузер).
- [ ] Раз в неделю делается разбор ошибок и приоритезация.

## 6) Готовность к переходу в прод

Переходить к реальным оплатам только когда:

- [ ] Gift-flow стабильно проходит e2e в dev/stage.
- [ ] Есть провайдер эквайринга РФ и подписанный договор.
- [ ] Подготовлены оферта/возвраты/ПДн.
- [ ] Настроены webhook-подписи и идемпотентность.
- [ ] Пройден тест возврата и корректного отключения доступа.
