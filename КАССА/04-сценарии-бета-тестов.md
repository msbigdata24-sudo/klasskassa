# Сценарии бета-тестов (gift-flow)

## A. Базовый happy path

- [ ] Плательщик создает gift-покупку (`/api/pro/gift/create`).
- [ ] Платеж подтверждается webhook (`paid` -> `PAID`).
- [ ] Получатель активирует gift-token (`/api/pro/gift/claim`).
- [ ] У получателя корректно выставлен `isPro` и `proUntil`.

## B. Негативные сценарии

- [ ] Некорректный токен -> 400.
- [ ] Просроченный токен -> статус `EXPIRED`, активация запрещена.
- [ ] Уже активированный токен -> понятная ошибка.
- [ ] Неоплаченный подарок -> активация запрещена.

## C. Конкурентность и дубликаты

- [ ] Два параллельных `claim` одним токеном -> только один успех.
- [ ] Повторный `create` с тем же `idemKey` -> тот же результат, без дубля.
- [ ] Дубликат webhook по одному платежу -> состояние не ломается.

## D. Возвраты

- [ ] Возврат до активации -> дальнейший claim запрещен.
- [ ] Возврат после активации -> доступ ограничивается по правилам продукта.
- [ ] Возврат может инициировать только плательщик (на уровне продукта/процесса).

## E. UX и поддержка

- [ ] На экране активации есть понятные тексты ошибок.
- [ ] В кабинете плательщика видны статусы покупки.
- [ ] Пользователь знает, куда писать при проблеме.

## F. Что фиксировать по каждому багу

- [ ] Шаги воспроизведения.
- [ ] Ожидаемое поведение.
- [ ] Фактическое поведение.
- [ ] Скрин/видео.
- [ ] Точное время и ID покупки/токен (маскированно).
