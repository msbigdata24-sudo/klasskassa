# Чат 2026-05-08: UX лендинга, ПДн/152-ФЗ, гости в группах

Краткая выжимка по основным темам и коммитам в репозитории **Апельсин** за сегодня.
Чат продолжается завтра — отсюда и поедем.

## 1. Метрики: сортировка групп и фильтр по периоду

- Раньше группы в `/personal/metrics` сортировались только по `totalEvents`, и
  выбранный период «1д / 7д / 30д» не применялся к запросу `lastEvents`.
- Добавлен переключатель **«По активности / По дате»** (`groupSortOptions`,
  тип `GroupSortKey`). По дате сортируем по `lastActivityAt`, далее по
  `totalEvents` и `membersCount`.
- К `prisma.activityEvent.groupBy` для `lastEvents` теперь применяются
  `createdAt: { gte: fromPeriod }` и `kind: { in: trackedGroupKinds }`. Группы
  без активности в выбранном периоде скрываются.
- Кнопки периода/сортировки сохраняют оба query-параметра (`period`, `sort`).

## 3. ПДн / 152-ФЗ — юридический минимум для беты

Решение по сути: имя + email — это персональные данные. На бете тестим без
регистрации в Роскомнадзоре, но честно описываем процесс и риски.

Что сделано:

- **Централизованный модуль `src/lib/legal-operator.ts`**: версия документов,
  дата вступления в силу, реквизиты Оператора (`fullName`, `inn`, `ogrnip`,
  `postalAddress` — пока **`[ЗАПОЛНИТЬ: …]`**), `contactEmail`,
  `telegramBetaInvite`, `telegramBetaTitle`, `dbHostingNote` (БД сейчас не в РФ,
  планируется перенос), хелпер `operatorIntroLine()`.
- **`/privacy`** переписана с нуля: 13 разделов под 152-ФЗ (категории ПДн,
  цели, основания, способы и сроки обработки, передача третьим лицам,
  трансграничная передача с честным описанием бета-этапа и плана переноса в
  РФ, cookies, права субъекта, удаление аккаунта/отзыв согласия, защита,
  изменения политики, контакты).
- **`/offer`** (Публичная оферта) переписана: 13 разделов, чётко указано, что
  Сервис **не платёжная система**, риски беты, правила регистрации,
  ответственность, ПДн со ссылкой на политику, применимое право, контакты.
- **`/contacts`**: явно «Оператор персональных данных» + «Связь» (email,
  Telegram), пометка про обращения по ПДн.
- **Чек-бокс согласия** в форме регистрации (`register-form.tsx`,
  обязательный, со ссылками на `/privacy` и `/offer`). Серверная проверка в
  `/api/auth/register`: `consent: z.literal(true).optional()` + явная проверка
  на `true`.
- **Cookie-плашка**: `src/components/cookie-consent.tsx`, подключена в
  `layout.tsx`. Запоминает выбор в `localStorage`, ссылка на политику.
- **Удаление аккаунта** через анонимизацию:
  - API `POST /api/auth/account/delete` — проверка пароля; в одной транзакции
    удаляются строго личные данные (DM, push-подписки, friend-links, Santa,
    notification settings), `actorId` в `ActivityEvent` зануляется,
    `User` обезличивается (email/name/passwordHash/Pro перезаписываются),
    финансовые записи (Expense, ExpenseSplit, Settlement, GroupMember)
    остаются в анонимизированном виде ради целостности групп. Логируется
    событие `ACCOUNT_DELETED`, сессионная cookie сбрасывается.
  - UI `src/components/delete-account-form.tsx` — пароль + ввод слова
    «УДАЛИТЬ». Форма встроена в `/personal` под красным `<details>`.
- **Возрастные ограничения** (важно): в оферте, пункт 4 — **самостоятельная
  регистрация с 14 лет**, но дети младше могут участвовать в группе как
  участники, добавленные взрослым (родителем/опекуном). Взрослый принимает на
  себя ответственность за обработку их ПДн.

## 4. Гости в группе без email (для детей и пр.) — `3933039`

Реализовано без миграции Prisma-схемы, на бете этого достаточно.

- **API `POST /api/groups/[id]/members`** теперь принимает либо `{ email }`,
  либо `{ guestName }`. В гостевом режиме создаётся `User` с фейковым email
  `guest-<uuid>@apelsin.guest` и placeholder-passwordHash
  `guest-account-no-login` (никогда не пройдёт `bcrypt.compare`).
  Push гостям не отправляется (нет subscription).
- **Форма `add-member-form.tsx`**: переключатель «По email / Гость без email»,
  пояснение про ответственность взрослого за ПДн ребёнка, `min-h-11`.
- **UI группы**: для гостя email скрыт (показывается «гость без входа»),
  кнопка «Написать в личку» для гостя не выводится.
- **`/api/auth/login` и `/api/auth/register`** блокируют домен
  `@apelsin.guest`: гость не может войти, и реальный пользователь не сможет
  занять зарезервированный домен.
- **Метрики** `/personal/metrics`: `totalUsers` и `activePro` теперь считаются
  с фильтром `email NOT endsWith "@apelsin.guest"` — гости не размывают MAU/DAU.
- **Утилита**: `src/lib/guest-user.ts` — `isGuestEmail`, `generateGuestEmail`,
  `GUEST_PASSWORD_HASH_PLACEHOLDER`.
